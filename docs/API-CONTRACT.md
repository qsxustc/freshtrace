# Core contract (v0.1)

`src/cache.js` is a browser-compatible ESM module with no dependencies or Node APIs.

`analyzeHeaders(input, options = {})` accepts a response header block or a plain header object. Only response caching headers are interpreted; assume a complete GET 200 response, a matching URL, and an unchanged stored representation. Options: `elapsed` nonnegative seconds since response receipt (default 0), `cacheType` `private` or `shared` (default private), `originError` boolean (default false), `authenticated` boolean (default false), `varyMatches` boolean (default true), optional `responseTime` and `requestTime` ISO strings or epoch milliseconds. If capture times are absent, assume receipt and request happen at the valid response Date; otherwise zero transit and no apparent age. Without Date or responseTime, Expires lifetime cannot be determined. Do not silently use the system clock.

Result fields: `headers` normalized object; `directives` array of `{name,value}`; `cacheType`; `baseAge`; `currentAge`; `freshnessLifetime` seconds or null; `freshnessSource` string; `staleWhileRevalidate` number; `staleIfError` number; `storeAllowed` boolean; `state` one of `fresh`, `swr`, `sie`, `revalidate`, `fetch`, `blocked`, `unknown`; `label` short English label; `reason` English explanation; `action` one of `cache`, `background-validation`, `validate`, `fetch`, `error`, `unknown`; `validator` `etag`, `last-modified`, or null; `warnings` array of English strings; `notes` array of English strings; `blockingStale` boolean; `vary` array.

Also export `parseHeaders(input)` normalized object and `parseCacheControl(value)` directive array. Invalid source shapes/options throw clear errors. Ambiguous/malformed cache policy must never become an optimistic fresh result. Handle no-store, no-cache, private/public, max-age, s-maxage, must-revalidate, proxy-revalidate, immutable (explained, no reload simulation), SWR/SIE, Age, Date/Expires, validators, Authorization permission and Vary. No heuristic TTL or CDN-specific override prediction. RFC 9111 and RFC 5861 are the sources. Qualified no-cache/private should be conservative and explicitly explained.
